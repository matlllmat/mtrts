                               Media Technology Repair Tracker System
1) Request Submission & Intake
Purpose: Provide an easy, structured way for end users to submit repair requests and for
the system to capture, validate, and route them correctly.
Primary Users:

    · Faculty
    · Department staff
    · Students
    · IT Help Desk
Core Features / Functional Requirements
    · Multi-channel intake:

             o Web portal (desktop/mobile responsive)
             o Email-to-ticket conversion
             o QR/barcode scan from asset tag to prefill asset details
    · Smart form:
             o Fields: Category (e.g., "Projector", "Sound System", "AV Switcher"), Asset ID,

                  Location/Room, Impact, Urgency, Description, Attachments (photo/video),
                  Preferred window/time, Event support flag (urgent pre-class request)
             o Dynamic fields based on category (e.g., "Bulb hours" for projectors, "Input
                  source" for switchers)
    · Autofill & validation:
             o Prefill user profile, contact, department from directory
             o Prefill asset details (model, warranty, vendor) after scan/lookup
             o Validate required fields and file type/size for attachments
             o Duplicate detection (same asset, same issue within N days)
    · Triage assist:
             o Auto-categorization and suggested KB articles based on description
             o Detect safety/urgent tags (e.g., room-wide outage) to fast-track priority
    · Routing:
             o Auto-assign to queue/team by location, category, or building
             o Optional approval workflow (e.g., for out-of-warranty or costly repairs)

    · Notifications:
             o Acknowledgement to requester with ticket ID and ETA window
             o Status change alerts (via email, push, or SMS where enabled)

Workflows
    1. Submit  Validate  Route  (Approve  Open Work Order
    2. Event-mode submission (short lead time)  escalated SLA  scheduled slot

Integrations
    · SSO/Directory (Azure AD/Entra ID, Google Workspace) for user profile
    · Email gateway for email-to-ticket
    · Asset DB/CMDB for lookup

Acceptance Criteria
    · As a requester, I can scan an asset tag to prefill details and submit in <60 seconds
    · Submitting via email creates a ticket with subject/body parsed, and attachments
         preserved
    · The system suggests at least one relevant KB article for 70%+ of tickets with free-
         text descriptions

2) Asset and Configuration Management
Purpose: Maintain authoritative records for media/AV assets, including warranty, location,
and history.
Primary Users: IT Helpdesk
Core Features / Functional Requirements

    · Asset registry:
             o Create, import (CSV), and bulk update assets
             o Fields: manufacturer, model, serial, asset tag, room/location, install date,
                  status (active/spare/retired), firmware, bulb hours (for projectors), network
                  info where applicable

    · Warranty & contracts:
             o Warranty terms, expiry, coverage type (parts/labor/onsite)
             o Auto alerts 60/30/7 days before expiry
             o Link SLA terms per vendor or contract

    · Relationship mapping:
             o Parent-child (e.g., AV rack  mixer, amp, switcher)
             o Room  assets mapping

    · History & documentation:
             o Attach manuals, wiring diagrams, configuration backups
             o Full repair & maintenance history linked to tickets/WO

    · Tagging & identification:
             o Generate/print QR/barcodes
             o Track ownership/cost center

Workflows
    · New asset onboarding  tag printing  room assignment  baseline photos/config
    · Warranty nearing expiry  batch check for outstanding issues  notification to
         manager

Validation & Business Rules
    · Serial numbers must be unique for same manufacturer
    · Cannot retire an asset with open tickets
    · Warranty end date > start date and  install date
3) Work Order & Dispatch Management
Purpose: Ensure every ticket is correctly classified, scheduled, assigned, and executed as
a work order.
Primary Users: IT Helpdesk Manager
Core Features / Functional Requirements

    · Queues & assignment:
             o Skill-based and location-based auto-assignment rules
             o Manual reassignment with notes

    · Work Order (WO)/Service Request generation:
             o One or more WOs per ticket (diagnosis, follow-up)
             o Include tasks/checklists per category (e.g., "Projector: lamp, filter, input
                  test")

    · Scheduling:
             o Calendar view by team/resource/room; avoid double-booking rooms and
                  technicians
             o Time windows, buffer times, travel time estimates

    · Parts & pre-check:
             o Pre-allocate parts from stock
             o RMA flag if under warranty

    · Status Management:
             o Example: New  Assigned  Scheduled  In Progress  On Hold (waiting
                  parts/vendor/access)  Resolved  Closed
             o Status can vary.

    · Knowledge aids:
             o Playbooks/triage scripts
             o Known issues by model/location
Validation & Business Rules
    · Mandatory checklist items must be completed before WO can be set to Resolved
    · SLA timers respect business hours and holidays
    · Can't schedule in a room that's booked for a class/event (if integrated)

4) Technician Operations (Mobile & Field)
Purpose: Equip technicians with a fast, offline-capable mobile experience to execute work
orders effectively.
Primary Users: IT Support
Core Features / Functional Requirements

    · Mobile app:
             o Secure sign-in (SSO, biometric if available)
             o Offline mode with later sync & conflict resolution
             o My Jobs list with priority indicators and travel time (optional)

    · WO execution:
             o Step-by-step checklist with required evidence (photos, videos,
                  measurements)
             o Time tracking (start/pause/stop) and labor categorization
             o Parts usage: scan parts, decrement stock, capture serials
             o Customer communication: call/message requester; arrival ETA
             o Sign-off capture: requester digital signature and satisfaction rating
             o Safety & pre-flight checks (ESD, power off, ladder safety, etc.)

    · Documentation:
             o Before/after media
             o Quick notes dictation (voice-to-text)
             o Attach configuration backups/logs
Validation & Business Rules
    · Can't close WO without mandatory fields, evidence, or signatures (configurable)
    · Offline entries must keep local audit hashes for forensics until synced

5) SLA, Reporting, Analytics & Audit
Purpose: Define service levels, ensure compliance, and provide insight for continuous
improvement.
Primary Users: IT Managers, Service Owners, Auditors, Executives
Core Features / Functional Requirements

    · SLA engine:
             o SLA policies by priority, location, category, request type (e.g., event support)
             o Working calendars, holidays, time-zone aware
             o Clock pause rules (awaiting parts/vendor/access)
             o Multi-stage targets: Response, Diagnosis, Resolution
             o Escalations: time-based, breach warnings, hierarchical on-call

    · Reporting:
             o Dashboards: backlog, aging, MTTR, FTFR, SLA compliance, cost per
                  ticket/asset, asset failure hotspots
             o Technician scorecards and heatmaps by building/room/time
             o Warranty exposure and upcoming expirations

    · Data access:
             o Export (CSV/Excel), scheduled report emails
             o BI connectors (e.g., OData/REST) with row-level security

    · Audit & compliance:
             o Immutable audit log for tickets, WOs, inventory, approvals
             o Data retention policies; PII minimization and masking
             o E-discovery support (searchable logs by date/user/object)
Workflows
    · SLA breach approaching  notify assignee & manager  auto-reprioritize or escalate
    · Monthly operations review: scheduled dashboard PDF to stakeholders

Validation & Business Rules
    · SLAs cannot be changed retroactively without audit justification
    · Row-level security ensures users only see data they're permitted to
